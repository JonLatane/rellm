# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Rellm (formerly Jonline; the checkout directory and some old docs/memory still say "jonline") is a decentralized, federated social network server. A single Rust binary serves gRPC (tonic) + gRPC-Web + HTTP (Rocket), and bundles the web frontends. Monorepo layout:

- `protos/*.proto` — the API contract. `rellm.proto` defines the `Rellm` service; other files hold messages. **Source of truth for every client.**
- `backend/` — Rust (edition 2024) server: tonic, Rocket, Diesel + Postgres, S3-compatible object storage (MinIO locally).
- `frontends/elm-spa/` — Elm SPA (elm-spa 6). The actively developed frontend; served by the backend at `/elm`.
- `frontends/tamagui/` — React/Next.js (Tamagui) frontend, yarn workspaces (`apps/next`, `apps/expo`, `packages/{api,app,ui}`). Served at `/tamagui`.
- `frontends/flutter/` — Flutter app (frozen). Its SDK is pinned in `.fvmrc` and managed with **FVM** — always `fvm flutter …`/`fvm dart …`, never a bare `flutter`/`dart`; first-time setup is `make -C frontends/flutter fvm_install` (see its README).
- `deploys/` — Kubernetes/Docker/release scripts (own Makefile); `docs/` — protocol docs generated from protos; `.github/workflows/` — CI/CD.

Repo-local skills in `.claude/skills/` (run-backend, run-elm, run-tamagui, rebuild-protos, elm-call-rpc, elm-add-panel, elm-add-drag-reorder, add-background-job) cover the detailed procedures below — use them.

## Commands

Root `Makefile` delegates to per-project Makefiles (`make run_backend|run_elm|run_tamagui`, `build_*`, `test_*`, `stop_dev_servers`, `run_tmux` for backend + Elm side by side).

**Protos** (after any edit under `protos/`): run `make` at repo root (= `protos docs graphs`). It regenerates Flutter (via FVM — `fvm` must be installed and `make -C frontends/flutter fvm_install` run once, plus `protoc` on PATH), Tamagui (`yarn protos`), and Elm (`make -C frontends/elm-spa protos`, needs `protoc-gen-elm`) bindings. Rust bindings regenerate in `cargo build` via `build.rs`; if stale, `cd backend && make rebuild_protos`. Generated files (`frontends/elm-spa/src/Proto/**`, `frontends/flutter/lib/generated/`, `backend/src/protos/`, Tamagui `packages/api/generated`) are committed.

**Backend** (`cd backend`; needs `backend/.env`, see `.env-example`: `DATABASE_URL`, `TEST_DATABASE_URL`, `MINIO_*`):
- `make local_object_storage_start run` — start MinIO docker container + `cargo run`. Listens on ports 80 and 8000 (gRPC) locally. `make local_instances_stop` kills it.
- `make local_db_create | local_db_reset | local_db_connect` — dev DB `rellm_dev`; `make local_test_db_create` for `rellm_test`.
- `cargo test` (separate test DB; migrations auto-applied on first run). Single test: `cargo test <name_substring>`; a file: `cargo test <file_stem>::` (e.g. `create_post_tests`).
- `make rebuild_elm_and_run` / `rebuild_tamagui_and_run` — rebuild a frontend and serve it through Rust (needed to verify routing/embedded assets).

**Elm** (`cd frontends/elm-spa`):
- `make run` (`npx elm-spa server`, port 1234); `make build` (production build; also the best way to get real compiler errors — `Gen.*`, `Request`, `Route` are generated by elm-spa, so bare `elm make` shows spurious missing-module errors).
- `make test` = `elm-review` then `npx elm-test-rs`; single file: `npx elm-test-rs tests/MarketTests.elm`. `make review_fix` autofixes lint.
- Prefer hand edits + `elm make`/`make build` over running `elm-format` on a file (it can reformat unrelated content).

**Tamagui** (`cd frontends/tamagui`): `make run` (`yarn web`), `make build` (tsc + build + next prod build; slow), `yarn test` (vitest). To type-check without the slow build: `make install_deps` (`yarn install --mode=skip-build`, once) then `make typecheck` (`yarn tsc --noEmit`, ~15s; or `make typecheck_tamagui` from the root). For a quick sanity check, prefer the backend's `rebuild_tamagui_and_run`.

## Backend architecture

- `main.rs` starts the tonic server (`servers/tonic.rs`, gRPC + gRPC-Web + reflection, optional TLS) and Rocket instances (`servers/rocket.rs`; public 80/443/8000, plus a separate internal-only port). Rocket mounts the SPA routes under `/`, `/tamagui`, and `/elm` — route ranks are deliberately explicit (see comments in `web/elm_web.rs`); `web/` also serves RSS/Atom/iCal feeds, media, sitemap, Stripe/contact webhooks.
- `rellm_service.rs` implements the generated `Rellm` trait. Each RPC is a thin wrapper using macros (`auth_rpc!`, `authenticated_rpc!`, …) that grab a DB connection, resolve the auth user (`auth/`), and call the real handler in `rpcs/<domain>/<rpc_name>.rs` (one file per RPC).
- Layering: `rpcs/` (handlers) → `logic/` (shared business logic: visibility/moderation, media, sync sources/destinations, market, AI, federation) → `models/` (Diesel structs + queries) → `schema.rs` (generated). `marshaling/` converts between Diesel models and proto messages (and DB ids ↔ proto id strings, `id_marshaling.rs`).
- Migrations are in `backend/migrations/` (Diesel). `diesel.toml` patches generated `schema.rs` via `diesel/schema.patch` — don't hand-edit `schema.rs`.
- `src/bin/*.rs` are standalone periodic/maintenance jobs (delete_expired_tokens, sync_sources, renew_market_subscriptions, …) with no central registry; new ones must be wired by hand into several files (see `add-background-job` skill, `background_jobs.sh`, deploys).
- Tests (`src/tests/*_tests.rs`) are DB-backed; build data with `tests/factories.rs` and wrap each body in `conn.test_transaction(...)`. Diesel "optimistic insert" patterns need their own inner `conn.transaction()` (savepoint) to work inside `test_transaction`.
- SPA catch-all routes (`spa_file_or_username_or_custom_tab`, `elm_file`) take `web::spa_path::SpaPath`, not `PathBuf`: Rocket's `PathBuf` guard rejects a final segment ending in `:`, which every short Bluesky post URL (`/~did:plc:…~rkey@bluesky:`) does.
- Link-preview metadata (`RellmSummary` → `<title>`/`og:*` in `web/spa_web_path.rs`) is user-controlled text: it always goes through `meta_text` (escapes `&<>"'`). Short URLs (`/~id`) are previewed by `web/short_url_preview.rs`; Bluesky posts get a cached lookup on Bluesky's fixed public API host, Mastodon posts a generic summary (never fetch a host taken from the request path).
- Gotcha: enum/list additions in protos (e.g. permissions) often need hand-maintained lists updated (`ALL_PERMISSIONS`, etc.) — grep for existing variants before calling a proto addition done.

## Elm frontend architecture

- elm-spa conventions: `src/Pages/**` are routes (file path = URL), `Shared.elm` holds app-wide model; `gen/` code is generated.
- `Effect.elm` wraps `Cmd` and adds `fromShared`, letting pages send messages to `Shared` (which owns global panels). App-wide overlay panels live in `src/Shared/*Panel.elm` and are driven from `Shared.Model` (see `elm-add-panel` skill). With multiple server instances, `Effect.fromShared` broadcasts can fan out per instance — dedup them or toggles cancel out.
- `src/Components/` are reusable views/data components; `src/UI/` is the shared widget kit (incl. `UI.Flip` for FLIP animations — see the reorder-cancels-CSS-transition note on its `remove` — and `UI.Drag` for drag-to-reorder on top of it; see the `elm-add-drag-reorder` skill).
- A `POST` quotes another post (or event) by putting its URL in `link` (`/post/id`, `/event/id`, `/~id`, any Rellm server); `Shared.QuoteLinks` (cache) + `Components.QuotedLink` (view) embed it, probing unknown hosts via `AccountsPanel` previews and caching non-Rellm hosts in `nonRellmHosts`. Bluesky/Mastodon post links (`Shared.Federation.FederatedLinks`) embed the same way, fetched directly from their networks. Links to Facebook/Instagram/LinkedIn/Pinterest/TikTok/X/YouTube posts always embed as sandboxed iframes (`src/SocialMediaEmbed/`, an Elm port of react-social-media-embed; iframe auto-resize is a `message` listener in `public/index.html`). There is no `embed_link` flag anymore. `/post/:id` of an EVENT/OCCASION redirects to `/event/:id` (`Pages.Post.PostId_`).
- The **Countabilibar** (`Shared.Countabilibar`, a row under the breadcrumbs) counts the posts/events `PostsPage`/`EventsPage` show per server (per user when there's one server) and lets you uncheck servers/users to hide them. Pages feed it after every `update` by diffing what they show against what's registered (`Countabilibar.syncMsg`, sent as `Shared.CountabilibarSync` -- a distinct constructor so `Main.notifyPageOfSharedMsg` can keep it while dropping echoes, and never notifies pages of it, see `Shared.notifiesPages`); hiding makes pages refetch with `excluded_author_user_ids` (see `applyHidden`). `Main` `reset`s it on every route change. Its FLIP reorder keeps the old order rendered until the old positions are measured -- an outgoing port's result can arrive after Elm has already painted (see `MeasurePhase`).
- **Infinite scroll** (`Components.Pages.PostsPage`, shared by the Posts page, Home and profiles; Recent, Popular and Following alike): every source (`ServerFeed`) keeps the cursor for its next page in `next` -- a Rellm server's `GetPosts.page` (the backend skips `PAGE_SIZE` = 200 rows per page; a shorter response is the last page, `rellmPageSize`), Mastodon's `max_id` (`offset` for trends), Bluesky's `cursor` -- and `Nothing` once it has run out. `PostsPage.Paging` (pure, `tests/PostsPagePagingTests.elm`) decides which loaded posts are safe to show while some source still has pages (nothing older than what an unfinished source has handed over so far, `Frontier`) and which `Window` of them is rendered: it grows by 25 as `<scroll-sentinel>` (a custom element in `public/index.html`, restarted by its `data-token`) reports the bottom, and drops posts from the top past 100 (the top sentinel brings them back). Posts leaving or arriving *above* the viewport swap without animation and `Ports.anchorScroll` re-scrolls to keep the post being read in place (`main.css` turns the browser's own scroll anchoring off); everything below animates through `UI.Flip` as usual. `Model.revealing` blocks the sentinels while new posts are still animating in, since they start collapsed and would read as a list that needs more.
- **Posts feed cache** (`Shared.PostsCache`, in memory only -- a page reload always refetches): `PostsPage` saves its loaded feeds, window and settings after every page landing / end reached (`storeEffect`), keyed by the page's path, and `PostsPage.init` restores them -- with no fetch and no enter animation -- only when `Main` marked the navigation as the browser's back button (`PostsCache.setRestoring`, set before `Pages.init`) and the snapshot's `Settings` match. Feeds expire 4 hours after they were *fetched* (`fetchedAt`, checked in `applyClock` once the page learns the time -- `Shared.time.now` is startup-only), and a restored feed older than 5 minutes shows a ⚠ button (`cacheAlertView`) left of the sort selector -- in the heading row, so it never shifts the posts -- whose popover (down-right) says when the posts were loaded. `Shared.update` (`postsCacheSync`) drops cached feeds the moment their server's acting account changes (sign-out, switch, disable), "Following" snapshots whenever accounts change, and snapshots with a post that is being deleted or a server a post was just created on. The clicked card is put back by `Ports.anchorScroll`'s sibling `restoreListAnchor` (JS records the clicked `[data-post-key]` card at click time and holds it in place for ~2.5s or until the reader touches the page).
- Backend calls go through generated `src/Proto/**` gRPC-Web bindings (see `elm-call-rpc` skill). The client talks to multiple Rellm servers (`Shared/AccountsPanel`, `Shared/Federation`); remote prod servers may lack newly added RPCs, so test writes against a local server.
- Use the run-elm driver (`.claude/skills/run-elm/driver.mjs`, Playwright) to verify UI/animation behavior in a live browser rather than relying on code reading.

## Conventions worth knowing

- Naming: the RSVP entity is `Rsvp`/`rsvps` (not `RSVP`/`event_attendances`). Mind proto import cycles (e.g. `users.proto` ↔ `sync.proto`); shared messages like `Author` are placed in a file both can import (currently `media.proto`).
- "MB"/"GB" in UI/code are binary (1024-based) everywhere.
- Glyphs, not emoji: iOS draws symbols like `↗` `◀` `▶` (anything with an emoji form) as color emoji unless followed by U+FE0E. Use `UI.Glyph` (`externalLink`, `left`, `right`, `play`, `textPresentation`) in Elm rather than typing them bare; `← → ↑ ↓ ▲ ▼ ✕ ✓` need nothing, and emoji-by-default symbols (`⏸` `➡`) can't be fixed this way -- draw those with CSS shapes (see `AudioPlayerPanel`).
- No `backdrop-filter` on always-present full-screen elements (`.shared-backdrop`, `.modal-backdrop`): even `blur(0px)` makes every repaint far slower, and `elm-style-animation` advances only 16.7ms per frame whenever a frame takes over 34ms -- so every Elm-driven animation (the Countabilibar's reorder, `UI.Flip`) crawls in slow motion. Closed state is `backdrop-filter: none`, which still transitions to/from `blur(...)`.
- Local dev DB/MinIO is not production; permission-gated features require granting permissions to a test account before smoke-testing.
- Deploys: CI (`.github/workflows/server_ci_cd.yml`) builds Tamagui + Flutter web + Rust, builds a Docker image, and deploys; K8s targets are in `deploys/Makefile` and exposed via root Makefile (`create_external_backend`, `update_external_backend`, …).
